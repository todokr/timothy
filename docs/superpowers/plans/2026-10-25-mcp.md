# MCP（tim mcp） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** メンバーの agent が `tim mcp` 経由でコメントを読み、HTML を直し、同じ URL に修正版を上げ、各コメントに返信できるようにする。レビュー対応の手順は MCP サーバーの `instructions` と prompt `address_comments` に同梱する。

**Architecture:** CLI に stdio の MCP サーバー（`@modelcontextprotocol/sdk`）を足し、`tim login` の資格情報（Bearer トークン）で API を呼ぶ。API には、ファイル情報と版の一覧を返す `GET /files/:id` と、保存された HTML をそのまま（ブリッジを差し込まずに）JSON で返す `GET /files/:id/content` を足す。返信・修正版・一覧は 1〜3 本目の API をそのまま使う。

**Tech Stack:** `@modelcontextprotocol/sdk`（stdio サーバー）と `zod`（CLI の新規依存）、commander、vitest。API 側は Hono。CLI は esbuild で 1 ファイル（`tim.mjs`）にバンドルして Homebrew で配っている。

**Spec:** `docs/superpowers/specs/2026-10-25-html-comments-design.md`（「MCP（`tim mcp`）」節、「レビュー対応の手順を同梱する」節、「誰が何をできるか」の MCP に関わる行）

本計画は 4 本のうちの 4 本目。1〜3 本目はマージ済み。

## Global Constraints

- `tim login` の資格情報で、ログインした本人として API を呼ぶ。
- ツールは `list_files`・`get_file`・`list_comments`・`reply_to_comment`・`upload_revision` の 5 つ。解決にするツールは作らない。
- `list_files` は自分がアップロードしたファイルだけを返す。
- Outdated かどうかは MCP では返さない。
- `get_file` の返り値に、配信用に差し込んだもの（ブリッジスクリプト）を含めない。これは API 側で保証する。
- 返信は「agent 経由」として記録する（CLI トークンでの返信は API が `viaAgent: true` にする。3 本目で実装済み）。
- 修正版は所有者以外は API が拒否する。
- レビュー対応の手順は MCP サーバーの `instructions` と prompt `address_comments`（引数はファイル ID）の両方に同じ内容で持つ。独立したスキル（SKILL.md）としては配らない。
- stdio の MCP サーバーは標準出力に JSON-RPC 以外を書かない（ログや案内は標準エラー出力へ）。
- CLI の `engines.node` は `>=18.2` のまま。
- コードのコメント・エラーメッセージの言語と書き方は既存ファイルに合わせる（コメントは日本語、API・CLI のエラーは英語）。ツールの説明と `instructions` は日本語。

## 設計者判断（仕様が触れていない点）

- **本文の取得 API は JSON で返す。** `GET /files/:id/content?v=<n>` は `{ id, version, html }` を返す。timothy と同じオリジンで HTML を `text/html` として返すと、アップロードされた JS が閲覧者のセッションで動いてしまうため。
- **要素の対象の `path` は MCP で返さない。** JS 実行後の DOM での位置なので、保存された HTML とは対応しない。agent には `tag` と `text`（文字範囲は `quote`・`prefix`・`suffix`）で突き合わせるよう `instructions` で伝える。
- **`list_comments` の既定は未解決だけ。** 引数 `includeResolved: true` で解決済みも含める。表示中の版で絞らず、全部の版のコメントを返し、各コメントに付けた版を入れる。
- **`upload_revision` の本文は、手元のファイルのパス（`path`）か HTML 文字列（`html`）のどちらか 1 つ。** 手元の生成元を直すのが手順の基本なので、パスを渡せるようにする。
- **`upload_revision` は確定（commit）が 5xx のとき 1 回だけやり直す。** 確定は `uploadId` ごとに冪等なので安全。
- **ファイルの指定は ID か共有 URL のどちらでもよい**（`tim upload --to` と同じ `parseFileRef` を使う）。
- **MCP の結果は JSON 文字列のテキストとして返す**（`content: [{ type: "text", text: JSON.stringify(result, null, 2) }]`）。エラーは `isError: true` と英語のメッセージ。

## Review Focus

1. `get_file` の HTML にブリッジ（`data-tim-bridge`）が入らない。`GET /files/:id/content` は `text/html` で返らない。→ Task 1
2. `tim login` していない状態で `tim mcp` を起動しても落ちず、各ツールが「`tim login` を実行してください」に当たる英語のエラーを返す。標準出力に JSON-RPC 以外が出ない。→ Task 3
3. 所有者以外・所有者なしの既存ファイルへの `upload_revision` は、API の理由（`Only the owner can upload revisions` など）をそのまま agent に返す。存在しない `path` は API を呼ぶ前にエラー。→ Task 3
4. 期限切れのファイル（410）や存在しないファイル（404）を指定したとき、ツールは分かる英語のエラーを返す。→ Task 2
5. `list_comments` が要素の `path` を含まず、既定で解決済みを除く。返信の書いた人に agent 経由かどうかが分かる。→ Task 3

- Modify: `packages/api/src/index.ts`

**Interfaces:**

- Produces（Task 2 が使う）:
  - `GET /files/:id` → `200 { id, title, description, url, owner: { email, name } | null, expiresAt: string | null, latestVersion: number, versions: { version: number, createdAt: string, uploadedBy: { email, name } | null }[] }`（`versions` は昇順）
  - `GET /files/:id/content?v=<n>` → `200 { id, version, html }`。`v` が無ければ最新版。

どちらもログインした人なら誰でも呼べる（閲覧と同じ）。`/files/*` には既に `ipAllowlist` と `requireUser("json")` が掛かっている。ファイルが無ければ `404 {"error":"Not Found"}`、期限切れなら `410 {"error":"Gone"}`（期限の判定は版の検証より先）、`v` が不正なら `404 {"error":"Not Found"}`。`/content` の応答には `Cache-Control: no-store` を付ける。`index.ts` で `app.route("/files", fileInfoRoute)` を他の `/files` ルートと並べる。

- Produces:

  - `server.ts`: `export function createServer(deps?: Partial<ServerDeps>): McpServer`。`ServerDeps` は Task 2 の関数と `apiList`・`apiUploadRevision`・`readConfig`・`readFile` を差し替えられるようにした型（テスト用）

ツール（名前・引数は下記のとおり。説明文は日本語で、何をするツールかと引数の意味を書く）:

| ツール | 引数 | 返すもの |
|---|---|---|
| `list_files` | なし | 自分のファイルの `{ id, title, url, latestVersion, createdAt, expiresAt }[]` |
| `get_file` | `file`（ID か共有 URL）、`version`（任意、整数） | `{ id, title, url, latestVersion, versions: { version, createdAt }[], version, html }` |
| `list_comments` | `file`、`includeResolved`（任意、既定 false） | `{ file: { id, title, latestVersion }, comments: [...] }`。各コメントは `{ id, version, anchor, author, createdAt, resolved, body, replies: { author, viaAgent, createdAt, body }[] }`。`author` は名前の文字列（返信で `viaAgent` なら名前の後に `（agent 経由）`）。`anchor` は文字範囲なら `{ type: "text", quote, prefix, suffix }`、要素なら `{ type: "element", tag, text }`（`path` は含めない） |
| `reply_to_comment` | `file`、`commentId`、`body`（1〜10,000 文字） | `{ commentId, replies: n }`（返信後の返信数） |
| `upload_revision` | `file`、`path`（任意）、`html`（任意） | `{ id, version, url }` |

- `file` が `parseFileRef` で読めなければ `Invalid file: <入力>`。
- `upload_revision` は `path` と `html` のちょうど 1 つが必要（どちらも無い・両方ある → `Specify exactly one of path or html`）。`path` は読めなければ API を呼ぶ前に `Cannot read file: <path>`。
- 設定（`apiEndpoint`）が無ければ `Run \`tim setup\` first`。資格情報が無い・401 は Task 2 のエラー文言のまま返す。
- 例外はすべて `isError: true` の結果に変換し、サーバーは落とさない。
- prompt `address_comments`（引数 `file`、必須）は、`REVIEW_WORKFLOW` に「対象のファイル: <file>」を添えた user メッセージを 1 つ返す。
- `tim mcp` は `StdioServerTransport` で接続する。起動時の案内も含め、標準出力には何も書かない。

`REVIEW_WORKFLOW` の内容（日本語。仕様の「手順に含める内容」1〜6 をそのまま手順にし、次を足す）:
- 要素のコメントは `tag` と `text` で、文字範囲のコメントは `quote` と前後の文脈（`prefix`・`suffix`）で HTML と突き合わせること。JS が描く図は HTML に文字として無いことがあり、その場合はユーザーに確認すること。
- 返信の例文「v<N> で〜を直しました」。
- 解決にはしないこと（ツールも無い）。
