# コメント Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 共有ページ `/s/:id` で、本文の文字範囲と DOM 要素にコメント・返信・解決ができるようにする。コメントは版をまたいで残り、表示中の版で対象を探し直して「Outdated」「非表示の要素」を控えめに示す。

**Architecture:** コメントは Firestore の `htmlFiles/{id}/comments/{commentId}` に持ち、返信はドキュメント内の配列に持つ。API は `/files/:id/comments` 以下。本体 HTML（`/s/:id/v/:n`）の配信時にブリッジスクリプトを差し込み、選択の検出・要素選択モード・ハイライト・対象の照合を iframe の中で行う。親画面（外枠ページ）とは `postMessage` でやり取りし、親画面は対象情報だけを渡し、コメント本文や書いた人は渡さない。iframe から来たメッセージで起きるのは、コメント欄を開いて対象を入れることと、外部リンクを新しいタブで開くことだけ。

**Tech Stack:** Hono（JSX）、firebase-admin（Firestore）、素の JavaScript を文字列で持つクライアントスクリプト（`webScript.ts` と同じ方式。バンドラは持ち込まない）、vitest、happy-dom（新規の devDependency。ブリッジの照合ロジックの単体テスト用）。

**Spec:** `docs/superpowers/specs/2026-10-25-html-comments-design.md`（「コメント」節の全部、「アップロードされた HTML の隔離」節のブリッジ部分、「誰が何をできるか」のコメント・返信・解決の行）。画面と操作の細部は試作 `.superpowers/brainstorm/41961-1792905960/content/prototype.html`（コミット対象外）を参考にする。ただし本計画と食い違うときは本計画に従う。

本計画は 4 本のうちの 3 本目。1 本目（ログインと所有者）と 2 本目（版）はマージ済み。4 本目（MCP）は本計画の `GET /files/:id/comments`・`POST /files/:id/comments/:cid/replies` と、Task 1 の `authMethod` を使う。

## Global Constraints

- 閲覧・コメント・返信はログインした人全員。所有者のいない既存ファイルにもコメントできる。
- 解決にする／未解決に戻すはブラウザからのみ。CLI トークン（MCP）からは 403。
- MCP（CLI トークン）からの返信は「agent 経由」として記録し、名前に「（agent 経由）」を添えて表示する。
- 新規コメントもブラウザからのみ（agent ができるのは返信まで）。〔設計者判断〕
- 通知は送らない。
- Outdated・非表示の要素は小さなラベルで示す。警告色や太い枠は使わない。
- 表示中の版より後の版で付いたコメントは出さない。過去の版を見ているときのコメントは、その版へのコメントになる。
- 「解決済みも表示」の既定は非表示。
- 要素選択モードは「◎ 要素を選んでコメント」ボタン、または ⌥+C（Windows は Alt+C）。キーは `KeyboardEvent.code === "KeyC"` と `altKey` で判定し、入力欄（input・textarea・select・contenteditable）にフォーカスがあるときは反応しない。
- モード中のクリックは HTML 側に渡さない。モード外のクリックはすべて HTML 側に渡す（外部リンクだけは後述のとおり親画面が開く）。
- 送信は ⌘+Enter（Windows は Ctrl+Enter）。IME の変換確定中（`isComposing` または `keyCode === 229`）は送信しない。
- 照合はブラウザ（ブリッジ）だけで行い、サーバーでは行わない。基準は JS 実行後の DOM。
- 対象が見つからなければ Outdated。別の箇所に付け替えない。
- 親画面は iframe へコメント本文や書いた人を渡さない。iframe からのメッセージは `event.source === iframe.contentWindow` で確かめ、`origin` は見ない（本体は不透明オリジンなので `"null"`）。親画面から iframe へは `"*"` で送る。
- 本体の CSP（`connect-src` の既定 `'none'`、sandbox に `allow-same-origin` なし）を変えない。ブリッジは既存の `'unsafe-inline'` の下でインライン実行する。nonce・hash を足さない（足すと `'unsafe-inline'` が無効になり、LLM が作った HTML が壊れる）。
- ブリッジは `serve.ts` の配信時にだけ差し込む。保存する HTML には入れない（4 本目の `get_file` は Storage から読む）。
- サーバー側にプロセス内状態を持たない。
- コードのコメント・エラーメッセージの言語と書き方は既存ファイルに合わせる（コメントは日本語、API のエラーは英語）。

## 設計者判断（仕様が触れていない点、または仕様・試作から変えた点）

- **外部リンクは親画面が開く。** 2 本目で外枠ページに `frame-src 'self'` を付けたため、本体の中で外部サイトへ移動できない。ブリッジがリンクのクリックを捕まえて親画面に URL を送り、親画面が `http:`・`https:` だけを `window.open(url, "_blank", "noopener,noreferrer")` で開く。iframe の中から `window.open` すると開いたタブも sandbox を引き継いで外部サイトが動かないため。仕様の「iframe から来たメッセージで起きてよいのは、コメント欄を開いて対象を入れるところまで」を、この 1 種類だけ広げる。ページ内リンク（同じ文書の `#…`）は今までどおり本体の中で動く。
- **文字範囲の文脈は前後 32 文字。** 同じ文字列が複数あるときは、保存した前後の文脈との一致が最も長い箇所を選ぶ。どの箇所とも文脈が 1 文字も一致しなければ Outdated。1 箇所しかなければ文脈は見ない。
- **要素の照合は仕様どおり。** 同じタグ（`localName`、SVG を含む）で要素内の文字（正規化して先頭 200 文字）が一致する要素がちょうど 1 つならそれ。そうでなければ本文ルート（`document.body`）からの位置が同じで同じタグの要素。どちらも無ければ Outdated。試作は文字が一致する要素が複数あると先頭を使うが、仕様の「無理に付け替えない」に従い使わない。
- **要素選択モードは「💬 この要素にコメント」を押した時点で終わる**（試作どおり）。
- **所有者が sandbox から `allow-scripts` を外したファイル**ではブリッジが動かない。コメントの一覧と返信・解決はできるが、本文での選択・ハイライト・ラベルは出ず、「◎ 要素を選んでコメント」は無効にして理由を出す。
- **本体のログイン切れ。** `/s/:id/v/:n` を未ログインで開くと、今は Google へリダイレクトして iframe の中でエラーになる。iframe 向けには 401 の小さな HTML（「ログインの有効期限が切れました。ページを再読み込みしてください。」）を返す。
- **`/s/:id#見出し`** は、外枠ページのスクリプトが iframe の `src` に `#見出し` を付け直して、本体の該当箇所へ移動させる。
- **入力の上限:** コメント本文・返信 10,000 文字、引用 1,000 文字、要素内の文字 200 文字（ブリッジが切り詰める）、位置の深さ 64、各位置 0〜100,000。

## Review Focus

1. 本体 HTML の JS が親画面へ偽のメッセージを送っても、コメントの送信・返信・解決は起きない。起きるのはコメント欄を開くこと（と外部リンクを開くこと）だけ。→ Task 6
2. 本体 HTML の JS は、閲覧者のセッションでコメント API を呼べない（不透明オリジン + `connect-src 'none'` + JSON 必須によるプリフライト）。コメントを書き込む API は JSON 以外を 415 で拒否し、CORS ヘッダを返さない。→ Task 3、Task 4
3. 要素選択モード中のクリックは本体の JS に届かない（タブが切り替わらない）。モード外のクリックはすべて届く。→ Task 5
4. 同じ文字列が 2 箇所ある本文で、文脈から正しい箇所を選ぶ。文言が変わった要素は位置とタグで追う。どちらでも決まらなければ Outdated で、別の箇所に付け替えない。→ Task 4
5. 修正版を上げてもコメントは消えない。ファイルを削除するとコメントも消える。→ Task 2

Firestore のフィールド: `version`、`anchor`、`body`、`authorEmail`、`authorName`、`createdAt`、`resolved`、`resolvedAt`、`resolvedByEmail`、`resolvedByName`、`replies`（`{ id, body, authorEmail, authorName, viaAgent, createdAt }` の配列）。コメント ID・返信 ID は `ulid()`。返信は `FieldValue.arrayUnion` で足す。

`parseAnchor` の規則:
- text: `quote` は空白を正規化（連続する空白を 1 つの半角空白、前後を trim）した後に 1〜`quote` 文字。`prefix`・`suffix` は文字列で `context` 文字以下（空文字可）。
- element: `tag` は `/^[A-Za-z][A-Za-z0-9-]{0,63}$/`（`localName`。HTML は小文字、SVG は `clipPath` などの大文字混じりがある）。`text` は文字列で `elementText` 文字以下（空文字可）。`path` は整数の配列で長さ 0〜`pathDepth`、各値 0〜`pathIndex`。
- 余計なキーは拒否する。

`parseNewComment`: `version` は 1〜`latest` の整数（範囲外は `version must be between 1 and <latest>`）。

### Task 3: コメント API

**Files:**
- Create: `packages/api/src/routes/comments.ts`、`packages/api/src/routes/comments.test.ts`
- Modify: `packages/api/src/index.ts`

**Interfaces:**
- Consumes: Task 1 の `getAuthMethod`、Task 2 の `parseNewComment`・`parseBody`・`listComments`・`createComment`・`addReply`・`setResolved`、`latestVersionOf`、`isJsonContentType`
- Produces（Task 6 と 4 本目が使う）:
  - `GET /files/:id/comments` → `200 { comments: CommentDto[] }`
  - `POST /files/:id/comments`、本文 `{ version, anchor, body }` → `201 { comment: CommentDto }`
  - `POST /files/:id/comments/:commentId/replies`、本文 `{ body }` → `201 { comment: CommentDto }`（返信を足した後のコメント全体）
  - `POST /files/:id/comments/:commentId/resolve`、本文 `{ resolved: boolean }` → `200 { comment: CommentDto }`

`/files/*` には既に `ipAllowlist` と `requireUser("json")` が掛かっている。`index.ts` で `app.route("/files", commentsRoute)` を他の `/files` ルートと並べる。

判定の順序とエラー:

| 条件 | 対象 | 応答 |
|---|---|---|
| Content-Type が JSON でない | POST 3 つ | `415 {"error":"Content-Type must be application/json"}` |

### Task 5: ブリッジの操作

**Files:**
- Create: `packages/api/src/lib/bridgeProtocol.ts`、`packages/api/src/lib/bridgeProtocol.test.ts`
- Modify: `packages/api/src/lib/bridge.ts`、`packages/api/src/lib/bridge.test.ts`

**Interfaces:**
- Consumes: Task 4 の `BRIDGE_ANCHOR_LIB` の関数
- Produces（Task 6 が使う）: `bridgeProtocol.ts` の `export const BRIDGE_MESSAGES` と、メッセージの形。すべてのメッセージは `{ tim: 1, type: <下記>, ... }`。

| 向き | `type` | 中身 | 意味 |
|---|---|---|---|
| 本体→親 | `tim:ready` | — | ブリッジが動き始めた |
| 本体→親 | `tim:compose` | `anchor` | コメント欄を開いて対象を入れてほしい |
| 本体→親 | `tim:key` | `key: "toggle-pick" \| "escape"` | iframe にフォーカスがあるときのショートカット |
| 本体→親 | `tim:pick-ended` | — | 本体側で要素選択モードが終わった |
| 本体→親 | `tim:anchor-states` | `states: Record<id, "attached" \| "hidden" \| "outdated">` | 照合の結果 |
| 本体→親 | `tim:focus-result` | `id`, `state` | カードを押したときの結果（トースト用） |
| 本体→親 | `tim:open-link` | `href` | 外部リンクを開いてほしい |
| 親→本体 | `tim:set-pick` | `on: boolean` | 要素選択モードの切り替え |
| 親→本体 | `tim:set-anchors` | `anchors: { id, anchor, highlight }[]`, `activeId: string \| null` | ハイライトする対象（未解決のもの）と照合する対象（表示中のもの全部）。本文・書いた人は含めない |
| 親→本体 | `tim:focus` | `id` | 該当箇所へスクロールして強調 |
| 親→本体 | `tim:clear-selection` | — | 文字選択を解除 |

`set-anchors` の `anchors` には、パネルに表示するコメント全部の `{ id, anchor, highlight: boolean }` を入れる（解決済みは `highlight: false`）。

ブリッジの振る舞い:
- 親からのメッセージは `event.source === window.parent` かつ `data.tim === 1` かつ既知の `type` だけ受け付ける。
- 画面に出す UI（「💬 コメント」「💬 この要素にコメント」、枠、トースト用の枠は無し）は、`document.documentElement` に足した `<div data-tim-bridge>` の Shadow DOM の中に置き、`position: fixed`・最大の `z-index` にする。ページの CSS の影響を受けない。
- **文字選択:** `selectionchange` で、選択が `document.body` 内で空でなければ、選択範囲の右下に「💬 コメント」を出す。ボタンの `mousedown` は `preventDefault`（選択を保つ）。押したら `timCaptureText` の結果を `tim:compose` で送り、ボタンを隠す。選択しただけでは何も送らない。要素選択モード中は出さない。
- **要素選択モード:** `window` のキャプチャフェーズで `click`・`mousedown`・`mouseup`・`pointerdown`・`pointerup`・`dblclick`・`auxclick`・`contextmenu` を受け、モード中だけ `preventDefault` と `stopImmediatePropagation` をする（ブリッジ自身の UI へのイベントは除く）。`mouseover` で点線の枠、`click` で実線の枠と「💬 この要素にコメント」を出す。押したら `timCaptureElement` の結果を `tim:compose` で送り、モードを終えて `tim:pick-ended` を送る。モード中は文字選択を解除する。
- **キー:** `keydown`（キャプチャ）で、`code === "KeyC"` かつ `altKey` かつ `ctrlKey`・`metaKey` が偽で、対象が入力欄でなければ `preventDefault` して `tim:key toggle-pick`。`Escape` はモード中ならモードを終えて `tim:pick-ended`、どちらの場合も `tim:key escape`。
- **ハイライト:** 文字範囲は CSS Custom Highlight API（`CSS.highlights` に `tim-comments` と `tim-comment-active`。スタイルは `document.adoptedStyleSheets` で足す）。要素は Shadow DOM 内の枠を重ねる（スクロール・リサイズで追従）。API が無い環境では何もしない。
- **照合の結果:** 見つからなければ `outdated`、見つかったが `getClientRects().length === 0` なら `hidden`、それ以外は `attached`。`set-anchors` を受けたとき、本文の DOM が変わったとき（`MutationObserver`、間引いて 300ms）、タブ切り替えなどで表示が変わったときに `tim:anchor-states` を送り直す。
- **フォーカス:** `tim:focus` で対象を中央へスクロールし、1.2 秒の強調枠を出し、`tim:focus-result` を返す。
- **リンク:** モード外の `click`（キャプチャ）で `closest("a[href]")` を見る。リンク先が今の文書と `#…` だけ違う（または同じ）ならそのまま。`http:`・`https:` で別の文書なら `preventDefault` して `tim:open-link`。それ以外のスキームは触らない。

- パネル: コメント欄（対象の表示・テキストエリア「コメントを書く…」・「コメント」「キャンセル」・「⌘+Enter / Ctrl+Enter で送信」）、待機中の案内「文字を選択するか、「要素を選んでコメント」で図などを選ぶと、その箇所にコメントできます」、「N 件の未解決コメント」、「解決済みも表示」チェック（既定オフ）、コメントの一覧。
- サーバーから `data-file-id`・`data-shown-version`・`data-latest-version`・`data-scripts-allowed`（`effectiveSandboxTokens` に `allow-scripts` があるか）を `<aside>` に出す。
- `data-scripts-allowed="false"` のときは「◎ 要素を選んでコメント」を `disabled` にし、パネルに「この HTML はスクリプトを許可していないため、本文を選んでコメントすることはできません」を出す。

親画面のスクリプト（`viewerScript.ts` の `VIEWER_SCRIPT`。既存の版セレクタの処理もここへ移す）:
- 読み込み時に `GET /files/<id>/comments` を取り、表示中の版以下（`version <= shown`）のコメントを、「解決済みも表示」がオフなら未解決だけ、作成順に描く。ユーザー由来の文字列はすべて `textContent` で入れる（`innerHTML` を使わない）。
- カード: 対象（文字範囲は `"引用"`、要素は `▢ 要素「要素内の文字の先頭 60 文字」`、空なら `▢ 要素 <tag>`）、書いた人（名前、`title` にメール）、ラベル（`Outdated`・`非表示の要素`・`解決済み`。どれも同じ控えめな枠線のラベル）、`v<版>・<YYYY-MM-DD HH:mm>`（Asia/Tokyo）、本文、返信（`viaAgent` なら名前の後に「（agent 経由）」）、「返信」「解決にする」／「未解決に戻す」。
- 0 件なら「この版にはまだコメントがありません」。
- ブリッジから `tim:ready` を受けたら、表示中のコメントの `{ id, anchor, highlight: !resolved }` と `activeId` を `tim:set-anchors` で送る。一覧が変わるたびに送り直す。`tim:anchor-states` でラベルを更新する。
- カードを押すと `activeId` にして `tim:focus` を送る。`tim:focus-result` が `outdated` なら「v<表示中> には引用箇所がありません。v<コメントの版> に切り替えると確認できます」、`hidden` なら「この要素はいま表示されていません（裏のタブなど）」をトーストで出す。
- `tim:compose` を受けたら、対象を `ANCHOR_LIMITS` で検証し（不正なら無視）、コメント欄を開いて対象を表示し、テキストエリアにフォーカスする。**送信はしない。**
- 送信は「コメント」ボタンか ⌘+Enter／Ctrl+Enter（IME 変換中は送らない）。`POST /files/<id>/comments` に `{ version: shown, anchor, body }`。表示中が最新版でなければ「過去の版へのコメントとして保存しました」をトーストで出す。成功したら一覧を取り直し、コメント欄を閉じ、`tim:clear-selection` を送る。失敗したらコメント欄の中にエラーを出し、入力は消さない。
- 返信・解決も同様に API を呼んで一覧を取り直す。返信欄も ⌘+Enter で送る。
- 要素選択モード: ボタン・⌥+C（親画面にフォーカスがあり、入力欄でないとき）・`tim:key toggle-pick` で切り替え、`tim:set-pick` を送る。`Escape`（親画面）か `tim:key escape` は、モード中ならモードを終え、そうでなくコメント欄が開いていれば閉じる。`tim:pick-ended` でボタンの見た目を戻す。
- `tim:open-link` は `new URL(href)` の `protocol` が `http:`・`https:` のときだけ `window.open(url, "_blank", "noopener,noreferrer")`。
- すべての受信メッセージは `event.source === frame.contentWindow` かつ `data.tim === 1` で確かめる。`origin` は見ない。送信は `frame.contentWindow.postMessage(msg, "*")`。
- `location.hash` があれば、読み込み時に iframe の `src` を `"/s/<id>/v/<shown>" + location.hash` にする。
