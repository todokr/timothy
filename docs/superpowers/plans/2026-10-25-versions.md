# 版（同じ URL に修正版を上げる） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 1 つの共有 URL に複数の版を持たせ、所有者が Web・CLI から修正版を上げられるようにする。`/s/:id` は timothy の画面になり、ヘッダーの版セレクタで版を切り替え、本体 HTML は sandbox 付きの iframe で表示する。

**Architecture:** v1 は今までどおり親ドキュメント（`htmlFiles/{id}`）の `storagePath`。v2 以降はサブコレクション `htmlFiles/{id}/versions/{n}` に持ち、親に `latestVersion` を置く（無ければ 1）。データ移行はしない。修正版のアップロードは 2 段階で、発行（署名付き URL と `uploadId` を返す）→ クライアントが PUT → 確定（オブジェクトの存在を確かめ、Firestore のトランザクションで次の番号を割り当てる）。番号を確定時に割り当てるので、PUT しないまま放棄されたアップロードは番号を消費しない。`/s/:id` はコメント UI の土台になる外枠ページ、本体は `/s/:id/v/:n` から配信する。

**Tech Stack:** Hono（JSX）、firebase-admin（Firestore トランザクション、`recursiveDelete`）、@google-cloud/storage、vitest、commander。新しい依存は追加しない。

**Spec:** `docs/superpowers/specs/2026-10-25-html-comments-design.md`（本計画は「版」節、「アップロードされた HTML の隔離」節のうち iframe 化と `X-Frame-Options` の緩和、「既存機能への影響」節の版に関わる項目を実装する）

本計画は 4 本のうちの 2 本目。1 本目（ログインと所有者、PR #28）の `SessionUser`・`getUser(c)`・`canManage()`・`requireUser()` を使う。3 本目（コメント）は本計画の外枠ページにコメントパネルとブリッジスクリプトを足し、4 本目（MCP）は本計画の `lib/versions.ts` と修正版 API を使う。

**本計画でやらないこと:** ブリッジスクリプト、`postMessage`、コメントパネル（3 本目）。MCP 用の本文取得 API（`get_file` 用。ブリッジを含まない生の HTML を返す。4 本目で `lib/versions.ts` の `getVersion()` を使って足す）。

## Global Constraints

- 版番号は 1 から振る連番。欠番を作らない。
- `/s/:id` は最新版を表示する。`/s/:id?v=2` は v2 を表示し、リロードしても同じ版が出る。
- 版ごとに別の Storage オブジェクトに保存し、過去の版を上書きしない。
- 既存ファイルは、今の `storagePath` を v1 として扱う。
- 有効期限は版ではなく共有 URL 単位で持つ（今と同じ）。期限切れなら、どの版を指定しても 410。
- 修正版のアップロードは最初にアップロードした本人のみ。`ownerEmail` の無い既存ファイルには誰も修正版を上げられない（`canManage()` とは別の判定）。
- 他サイトからの埋め込みは引き続き拒否する。外枠ページは `X-Frame-Options: DENY`、本体だけ `SAMEORIGIN`。
- サーバー側にプロセス内状態を持たない。
- `POST /upload` の入出力は変えない（1 本目の CLI がそのまま使っている）。
- コードのコメント・エラーメッセージの言語と書き方は既存ファイルに合わせる（コメントは日本語、API のエラーは英語）。

## 設計者判断（仕様が触れていない点）

- 修正版ではタイトル・説明・有効期限を変えない。これらは共有 URL の属性とする。CLI は `--to` と `--title`・`--ttl` の併用を拒否する。〔ビルダー判断〕
- 修正版を上げた人は所有者本人に限られるが、版ごとに `uploaderEmail`・`uploaderName` を記録しておく（3 本目で「付けた版」と並べて表示しうるため）。〔ビルダー判断〕
- iframe に `sandbox` 属性は付けない。属性はレスポンスの CSP `sandbox` と積集合になり、所有者がヘッダ設定で許可したトークンを黙って打ち消すため。隔離は本体の CSP `sandbox`（`allow-same-origin` 無し）が担う。〔ビルダー判断〕
- 放棄された修正版のオブジェクト（PUT 済みで確定されなかったもの）はファイル削除時に prefix ごと消す。それ以外の掃除はしない。〔ビルダー判断〕

## Review Focus

1. 所有者以外・所有者なしの既存ファイルへの修正版は 403 で、Firestore にも Storage にも何も書かれない（署名付き URL も発行しない）。→ Task 2
2. PUT せずに確定を呼ぶと 409 で、`latestVersion` は変わらない。同じ `uploadId` で確定を 2 回呼んでも版は 1 つしか増えない。→ Task 1, Task 2
3. 同時に 2 つの修正版を確定すると、番号は N と N+1 になり、重複も欠番もない。→ Task 1
4. `?v=abc`・`?v=0`・`?v=99`（最新より大きい）・`?v=1.5` は 404。黙って最新版に落とさない。→ Task 4
5. ファイルを削除すると、v1・v2 以降・確定されなかったアップロードのオブジェクトがすべて消え、`versions` サブコレクションも消える。→ Task 3

- Produces（後続タスクと 3・4 本目が使う）:
  - `export const VERSIONS_SUBCOLLECTION = "versions"`
  - `export type FileVersion = { number: number; storagePath: string; createdAt: Date; uploader: { email: string; name: string } | null }`
  - `export function latestVersionOf(data: DocumentData): number` — `data.latestVersion` が正の整数ならそれ、無ければ 1
  - `export function parseVersionParam(raw: string | undefined, latest: number): number | null` — `undefined` は `latest`。`/^[1-9]\d*$/` に合わない、または `latest` より大きければ `null`
  - `export async function getVersion(fileId: string, data: DocumentData, n: number): Promise<FileVersion | null>` — n=1 は親の `storagePath`・`createdAt`・`ownerEmail`/`ownerName`（無ければ `uploader: null`）から組み立てる。n≥2 は `versions/{n}` を読む
  - `export async function listVersions(fileId: string, data: DocumentData): Promise<FileVersion[]>` — v1 を先頭に、番号の昇順
  - `export function isUploadId(value: string): boolean` — ULID（`/^[0-9A-HJKMNP-TV-Z]{26}$/`）
  - `export function revisionStoragePath(fileId: string, uploadId: string): string` — `timothy-files/<fileId>/rev-<uploadId>.html`
  - `export function revisionPrefix(fileId: string): string` — `timothy-files/<fileId>/`
  - `export type RevisionDenial = "gone" | "no_owner" | "forbidden"`
  - `export function revisionDenial(user: SessionUser, data: DocumentData, nowMs?: number): RevisionDenial | null` — 期限切れ（`expiresAt` が過去）→ `"gone"`、`ownerEmail` 無し → `"no_owner"`、`canRevise` が偽 → `"forbidden"`
  - `export type CommitResult = { ok: true; version: number } | { ok: false; reason: "not_found" | RevisionDenial | "content_missing" }`
  - `export async function commitRevision(p: { fileId: string; uploadId: string; user: SessionUser }): Promise<CommitResult>`
  - `ownership.ts`: `export function canRevise(user: SessionUser, data: { ownerEmail?: string | null }): boolean` — `ownerEmail` があり、大文字小文字を無視して一致するときだけ真
  - `storage.ts`: `export async function fileExists(storagePath: string): Promise<boolean>`、`export async function deleteFilesWithPrefix(prefix: string): Promise<void>`

版ドキュメント `htmlFiles/{id}/versions/{n}`（ドキュメント ID は `String(n)`）のフィールド: `number`、`storagePath`、`createdAt`（`now()`）、`uploaderEmail`、`uploaderName`。親には `latestVersion` を更新する。

`commitRevision` の手順:
1. 親を読む。無ければ `not_found`。`revisionDenial` が非 null ならその理由。
2. `fileExists(revisionStoragePath(...))` が偽なら `content_missing`。
3. `db.runTransaction` の中で、親を読み直して 1 の判定をもう一度行い、`versions` を `storagePath == path` で引く。あればその番号を返す（冪等）。無ければ `n = latestVersionOf(親) + 1` で `tx.create(versions/{n})` し、親の `latestVersion` を `n` に更新する。

  - `POST /files/:id/versions` → `200 { uploadId: string, uploadUrl: string, uploadHeaders: { "Content-Type": "text/html; charset=utf-8" } }`
  - `POST /files/:id/versions/:uploadId/commit` → `200 { id: string, version: number, url: "<base>/s/<id>?v=<n>" }`

両エンドポイントとも、本文は `{}` でよいが `Content-Type: application/json` を必須にする（ブラウザのセッションで呼ばれるため、`<form>` からのクロスサイト送信を塞ぐ。`upload.ts` と同じ理由）。`/files/*` には既に `requireUser("json")` が掛かっている。

エラーの対応（判定の順もこのとおり）:

| 条件 | 応答 |
|---|---|
| Content-Type が JSON でない | `415 {"error":"Content-Type must be application/json"}` |
| `uploadId` が ULID でない（commit のみ） | `400 {"error":"Invalid upload id"}` |
| ファイルが無い | `404 {"error":"Not Found"}` |
| `gone` | `410 {"error":"Gone"}` |
| `no_owner` | `403 {"error":"Revisions are not allowed for files without an owner"}` |
| `forbidden` | `403 {"error":"Forbidden"}` |
| `content_missing`（commit のみ） | `409 {"error":"Uploaded content not found"}` |

- Produces（3 本目が足す）: 外枠ページの DOM。ヘッダーは `<header data-viewer-header>`、本体は `<iframe id="viewer-frame" src="/s/<id>/v/<n>">`。3 本目はこの横にコメントパネルを置き、ヘッダーに「◎ 要素を選んでコメント」を足す。

`GET /s/:id?v=<n>`:
- ファイルが無い → `404 {"error":"Not Found"}`、期限切れ → `410 {"error":"Gone"}`（今の `/s/:id` と同じ）。
- `parseVersionParam(c.req.query("v"), latest)` が null → 404。
- ページの中身: タイトル、表示中の版と最新版の番号（例「v2 / 全 3 版」）、版セレクタ、iframe。最新版でない版を表示しているときは「最新版ではありません」と最新版へのリンクを出す。
- 版セレクタは `<select>` で、各 `<option>` は「v<N>（YYYY-MM-DD HH:mm）」、表示中の版を `selected`。変更したら `?v=<N>` へ移動する（小さなインラインスクリプト。最新版を選んだときも `?v=<latest>` にする）。JS が無くても版を切り替えられるよう、`<noscript>` に各版へのリンクを並べる必要はない（timothy の Web 画面は JS 前提）。
- iframe に `sandbox` 属性を付けない（「設計者判断」参照）。`title` 属性にファイルのタイトルを入れる。iframe は画面の残りの高さいっぱいに広げる。
- ヘッダ: `X-Frame-Options: DENY`、`Content-Security-Policy: frame-ancestors 'none'`（`auth.tsx` の確認画面と同じ）、`Cache-Control: no-store`。
- `index.ts` では `app.route("/s", viewerRoute)` を `serveRoute` と並べて登録する。`/s/*` の `requireUser("redirect")` がそのまま効く。
