# 共有 HTML へのコメントと修正版

## 背景

メンバーが LLM で作った詳細設計などの HTML を timothy で共有し、レビューを受ける使い方が増えた。
いまはレビューのやり取りを Slack で行っており、「〇〇のところですが」と本文を引用しながら
書く手間がかかる。直した版は新しい URL になるので、どの指摘がどの版で直ったのかも追いにくい。

これを timothy の中で完結させる。

1. レビュアーは共有 URL を開き、本文の文字や図の要素を指してコメントする
2. メンバーは自分の agent に「timothy のコメントを見て直して」と頼む。agent は MCP で
   コメントを読み、HTML を直し、**同じ URL に修正版を上げ**、各コメントに返信する
3. レビュアーは同じ URL を開き直し、修正版とこれまでのコメントを並べて確認し、解決にする

「コメントしたよ」「直したよ」の連絡は、今までどおり Slack で人が一言伝える。timothy から通知は送らない。

体験の確認用に作った使い捨ての試作が
`.superpowers/brainstorm/41961-1792905960/content/prototype.html` にある（コミット対象外）。
画面と操作の細部は、迷ったら試作の挙動を正とする。ただし試作には認証・iframe による隔離・
永続化がないので、それらは本書に従う。

## ゴール

- 共有 HTML の**文字範囲**と**DOM 要素**（図の箱、SVG の図形、表のセルなど）にコメントできる
- コメントにスレッドで返信でき、「解決にする」で畳める
- 同じ URL に修正版を上げられる。閲覧者は最新版を見て、過去の版にも切り替えられる
- メンバーの agent が `tim mcp` 経由でコメントを読み、返信し、修正版を上げられる
- 閲覧・コメント・アップロードのすべてに Google ログインを求める

## ゴールにしないもの

- 通知（Slack・メール連携）
- HTML ごとの閲覧者の指定。ログインできた人は全部の HTML を見られる
- agent によるコメントの解決。agent ができるのは返信まで
- 裏のタブに隠れた要素を、コメントから自動で表示させること（HTML ごとに作りが違うため）
- コメント付きの PDF 出力など、timothy の外への書き出し

## 失敗とみなすもの

次のどれかが起きたら、動いていても失敗とする。

- タブ切り替えなど、HTML 側の普段のクリック操作がコメント機能に横取りされる
- アップロードされた HTML の JS が、閲覧者の権限でコメントの投稿・ファイルの削除・
  一覧の取得などをできてしまう
- 修正版を上げると、過去のコメントが消える、または黙って別の箇所に付け替わる
- 引用箇所が消えたコメントが、強い警告として画面を占有する（目立ちすぎ）

## アカウントと権限

### ログイン

- Google アカウントでログインする。許可するドメインは環境変数（例: `ALLOWED_EMAIL_DOMAINS=assured.inc`）で指定する。
  timothy はセルフホストの OSS なので、ドメインをコードに書き込まない。
  ID トークンの `hd` クレームと `email_verified` で判定する。
  未設定のときは起動を拒否する（設定漏れで全 Google アカウントに開かないように、閉じる側に倒す）。〔設計者判断〕
- ログインを求める範囲は、Web 画面（一覧・アップロード・ヘッダ設定）、共有ページ `/s/:id`、
  API（`/upload`・`/files`・コメント API）の全部。`/health` だけは除く。
- ブラウザでは、未ログインで共有 URL や Web 画面を開くと Google のログイン画面へ送り、ログイン後に元の URL
  （版の指定 `?v=` を含む）へ戻す。セッションは Cookie で持つ。CLI を使わない人はこれだけで閲覧・コメント・
  Web からのアップロードと修正版のアップロードができ、`tim login` は要らない。
- 既存の `ALLOWED_IPS` はそのまま残し、ログインと併用する。

### 誰が何をできるか

| 操作 | できる人 |
|---|---|
| 閲覧・コメント・返信 | ログインした人全員 |
| 解決にする／未解決に戻す | ログインした人全員（ブラウザからのみ。MCP からはできない） |
| 修正版のアップロード | 最初にアップロードした本人のみ（Web・CLI・MCP のどこからでも） |
| 新規アップロード | ログインした人全員 |
| 削除・ヘッダ設定の変更 | 本人のみ。所有者のいない既存ファイルはログインした人全員 |

アップロード時に、アップロードした人のメールアドレスを所有者としてファイルに保存する。
所有者のいない既存ファイル（本機能より前のアップロード）は、誰も修正版を上げられない。
閲覧とコメントは普通にできる。削除とヘッダ設定の変更は、無期限の既存ファイルを誰も消せなくなるのを避けるため、
ログインした人なら誰でもできる（今と同じ）。

一覧（Web 画面・`tim list`）には全員分のファイルを出し、所有者の列を足す。「自分のファイルだけ」に絞り込める。
MCP の `list_files` は自分のファイルだけを返す。

### CLI の認証

- `tim login` でブラウザを開き、Google でログインして、CLI 用の資格情報を
  `~/.config/timothy/` に保存する。`tim upload`・`tim list`・`tim delete`・`tim mcp` はこれを使う。
- 資格情報の形式と発行方法（API が発行する個人トークンを loopback リダイレクトで受け取る、など）は
  ビルダーに任せる。ただし Cloud Run と AWS Lambda の両方で動くよう、サーバー側にプロセス内の状態を持たないこと。

## 版

- 1 つの共有 URL（`/s/:id`）に複数の版がぶら下がる。版番号は 1 から振る連番。
- `/s/:id` は最新版を表示する。過去の版はヘッダーの版セレクタで切り替える。版を指す URL
  （例: `/s/:id?v=2`）も用意し、リロードしても同じ版が出るようにする。
- 修正版のアップロードは、既存の `/upload` と同じく署名付き URL へ PUT する方式でよい。
  版ごとに別の Storage オブジェクトに保存し、過去の版を上書きしない。
- 既存ファイルは、今の `storagePath` を v1 として扱う。データ移行の要否はビルダーに任せる。
- 有効期限は版ではなく共有 URL 単位で持つ（今と同じ）。

## コメント

### 付け方

**文字範囲**
- 本文の文字を選択すると、選択範囲のそばに小さな「💬 コメント」ボタンが出る。
- ボタンを押して初めて、右パネルにコメント欄が開く。選択しただけでは何も起きない（コピー目的の選択を邪魔しない）。
- テキスト選択はモード切り替えなしで常に使える。

**DOM 要素**
- ヘッダーの「◎ 要素を選んでコメント」ボタン、または **⌥+C（Windows は Alt+C）** で要素選択モードを切り替える。
  ⌥ を押すと Mac は入力文字が変わるので、キーは `KeyboardEvent.code` で判定する。入力欄にフォーカスがあるときは反応しない。
- モード中は、カーソル下の要素に点線の枠が出る。クリックすると、その要素に実線の枠と
  「💬 この要素にコメント」ボタンが出る。ボタンを押して初めてコメント欄が開く。
- モード中のクリックは HTML 側に渡さない（タブが切り替わらない）。モード外のクリックはすべて HTML 側に渡す。
- コメントを 1 件書くか、Esc を押すとモードが終わる。

**送信**
- コメント欄・返信欄とも ⌘+Enter（Windows は Ctrl+Enter）で送信する。IME の変換確定中の Enter では送信しない。

### 表示

画面構成は試作のとおり。左に HTML、右にコメントパネル。

- パネルの各コメントに、対象（引用した文字、または「▢ 要素『要素内の文字』」）、書いた人、
  付けた版、日時、本文、返信を表示する。
- 解決していないコメントの引用箇所は、本文上でハイライトする。カードをクリックすると本文の該当箇所へスクロールし、強調する。
- **Outdated**: 表示中の版で対象が見つからないコメントには、GitHub の PR と同じく小さな「Outdated」ラベルを付ける。
  警告色や太い枠は使わない。
- **非表示の要素**: 対象は見つかったが表示されていない（裏のタブなど）コメントには「非表示の要素」ラベルを付ける。
  クリックしたときは、その旨をトーストで伝える。
- 「解決済みも表示」チェックで、解決済みのコメントの表示を切り替える。既定は非表示。
- 表示中の版より後の版で付いたコメントは出さない。過去の版を見ているときにコメントすると、その版へのコメントになる。
- MCP 経由で書かれた返信は、書いた人の名前に「（agent 経由）」を添えて表示する。

### 対象の記録と、版をまたいだ追跡

コメントを書いた版で対象を記録し、別の版を表示するときに探し直す。

- **文字範囲**: 選択した文字列（空白は正規化）を保存する。同じ文字列が本文に複数あると取り違えるので、
  前後の文脈も保存して絞り込む（試作は文字列だけで探しており、この点は未実装）。
- **DOM 要素**: タグ名、要素内の文字（正規化）、本文ルートからの位置を保存する。
  探し直すときは、まず同じタグで要素内の文字が一致するものを探す。一意に決まらなければ、同じ位置にある同じタグの要素を使う。
  修正で要素内の文言が変わっても、位置が同じならコメントは付いたままになる（試作の v4 で確認できる）。
- どちらでも見つからなければ Outdated とする。別の箇所に無理に付け替えない。
- 記録と照合の基準は、ブラウザで JS が動いた後の DOM とする。JS が描く図や表にもコメントできるようにするため。
  そのため、照合はブラウザ（ブリッジスクリプト）だけで行い、サーバーでは行わない。〔設計者判断〕

## アップロードされた HTML の隔離

今は `/s/:id` が HTML を直接返し、CSP の `sandbox` で不透明オリジンに閉じ込めている。
ログインを入れると閲覧者のセッションが生まれるので、HTML の JS がその権限を使えないことを守り続ける必要がある。

- `/s/:id` はコメント UI を持つ timothy の画面にする。HTML 本体は別の URL から配信し、sandbox 付きの
  iframe で表示する。本体の配信にも、今の CSP の床（sandbox・送信系の制限）をそのまま適用する。
- 選択の検出・要素選択モード・ハイライト・ショートカットは iframe の中でしか処理できない。そこで本体に小さな
  ブリッジスクリプトを差し込み、親画面と `postMessage` でやり取りする。iframe にフォーカスがあるときの
  ⌥+C・Esc もブリッジが親画面へ転送する。
- ブリッジへのメッセージは HTML 側の JS から偽造できる前提で設計する。親画面は iframe へ
  コメント本文や書いた人を渡さず、ハイライトに必要な対象情報だけを渡す。iframe から来たメッセージで
  起きてよいのは、コメント欄を開いて対象を入れるところまで。送信は親画面でのユーザー操作に限る。
- 今の `X-Frame-Options: DENY` は、本体を自分の画面の iframe に入れるために緩める必要がある。
  他サイトからの埋め込みは引き続き拒否する。
- **`allow-same-origin` は廃止する**。これを付けた HTML は timothy と同一オリジンで動き、閲覧者のセッションで API を叩けてしまうため。
  `ALLOW_UNSANDBOXED_CONTENT` と、sandbox 設定の語彙から `allow-same-origin` を外す。既に保存された設定に含まれていても、
  配信時には無視する（`availableSandboxTokens()` で読み取り側も絞っている今の作りに合わせる）。

## MCP（`tim mcp`）

CLI に stdio の MCP サーバーとして同梱する。`tim login` の資格情報で、ログインした本人として API を呼ぶ。

用意するツールの目安（名前と引数の細部はビルダーに任せる）:

| ツール | 内容 |
|---|---|
| `list_files` | 自分がアップロードしたファイルの一覧 |
| `get_file` | 指定した版（既定は最新）の HTML 本文と、版の一覧 |
| `list_comments` | コメント一覧。対象（引用文字列と前後の文脈、または要素のタグと要素内の文字）、付けた版、書いた人、本文、返信、解決済みか |
| `reply_to_comment` | コメントに返信する。返信は「agent 経由」として記録する |
| `upload_revision` | 修正版を上げる。所有者以外は API が拒否する |

- 解決にするツールは作らない。
- 最新版で対象がまだ付いているか（Outdated か）は MCP では返さない。サーバーは JS 実行後の DOM を持たず、
  静的に判定すると画面の表示と食い違うため。agent は `get_file` で取った HTML とコメントの対象を突き合わせて自分で判断する。〔設計者判断〕
- 返り値のイメージは試作の「MCP で agent に渡る内容」ボタンで見られる。

### レビュー対応の手順を同梱する

ツールだけでは、agent はレビュー対応の進め方を知らない。手順を `tim mcp` に同梱し、メンバーが別にスキルを
入れなくても「timothy のコメントを見て直して」と頼むだけで手順どおりに動くようにする。
独立したスキル（SKILL.md）としては配らない。ツールと手順の版がずれないようにするため。

- **MCP サーバーの `instructions`** に手順を書く。接続するだけで agent の文脈に入る。
- **MCP の prompt**（例: `address_comments`、引数はファイル ID）として同じ手順を用意し、明示的にも呼べるようにする。

手順に含める内容:

1. `list_comments` で未解決のコメントを読み、`get_file` で最新版の HTML を取る。
2. コメントの対象と最新版の HTML を突き合わせ、既に直っているもの（Outdated 相当）を見分ける。MCP は Outdated かどうかを返さない。
3. 直すのは手元にある元の HTML、またはその生成元のファイル。手元に無いときだけ `get_file` の内容を直す。
   配信用に差し込まれたもの（ブリッジスクリプトなど）が `get_file` の返り値に含まれないことは API 側で保証する。
4. 方針がはっきりしない指摘は、直さずにユーザー（メンバー本人）に確認する。
5. `upload_revision` で修正版を上げてから、対応したコメントに「v<N> で〜を直しました」と返信する。
   直さなかったコメントにも理由を返信する。
6. コメントを解決にはしない（ツールも無い）。解決はレビュアーが判断する。

## 既存機能への影響

- Web 画面のアップロードは、ログインしたユーザーとして行う。一覧に修正版の導線（自分のファイルだけ）を足す。
- `tim upload` は、ファイル ID を指定して修正版を上げられるようにする（オプション名はビルダーに任せる）。
- `ALLOW_UNSANDBOXED_CONTENT` を廃止するので、README・ヘッダ設定画面の該当記述を消す。
- 共有ページが iframe 構成になるので、README の「共有ページは他サイトからの iframe 埋め込みを拒否する」の記述は
  挙動に合わせて書き直す。

## ビルダーに任せること

- 認証方式の実装（セッションの持ち方、CLI トークンの発行と失効、CSRF 対策）
- Firestore のデータ構造（版・コメント・返信をどう持つか）とインデックス
- コメント API のエンドポイント設計
- 本体 HTML を配信する URL の形と、ブリッジスクリプトの差し込み方
- 試作にない細部の見た目
